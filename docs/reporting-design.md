# POS reporting and audit extension

Keep the root menu unchanged. Add native SQLite schema v3 reporting in oobpos and a Flutter reports screen using TransactionHeading, navy pills and the original fonts. Default reporting timezone Asia/Manila, calendar days, Monday–Sunday weeks, calendar months. Sales are recognized by authoritative payment approval, not submission; tender/change are not revenue. Group cashier and payment method by accepted snapshots.

Persist a sales ledger, chained HMAC journal, immutable saved report snapshots, business profile snapshots, and print-request trail. The Android Keystore holds the journal HMAC key. Update ledger, grand total, order/payment and journal in the same SQLite transaction. Triggers prohibit update/delete of ledger/journal/reports. Import earlier payments once with an explicit migration event, without inventing tax details. X is a non-closing saved day snapshot. Z closes one day once, requires owner unlock, and blocks subsequent approvals dated on or before the latest closed day. Calendar summaries can be refreshed; saved copies retain their generation cutoff. Never reset lifetime sales.

Expose reports only to local native UI, no HTTP routes. Owner authentication protects business details and Z close. Print from native Android PrintManager using locally generated PDFs; preserve saved originals and log each print request/reprint before opening the spooler. A print request is not evidence of physical output. Include audit and reports in JSON export. Android save/print requires no internet; thermal printers require an installed compatible print service or a later model-specific adapter.

Tradeoff: app-level append-only records and Keystore HMAC detect edits, but cannot establish absolute immutability against root access, deleting all app data, or restoring a complete older database. Independent retained exports are necessary evidence; there is no remote witness in this offline architecture. Do not advertise BIR accreditation. Printed payment records explicitly state not a tax invoice pending accreditation and tax/discount/invoice work. Capture real registration fields through owner settings, never fabricate TIN/PTU/model accreditation.

Verify native period boundaries, money and tender math, renamed methods, migration/restart, append-only guards, HMAC validation, duplicate approval/Z retries, close-day enforcement and local-only authority. Verify Flutter report interaction and pill layout; build/install POS APK and inspect emulator. Actual printer and two-tablet physical testing remain separate.

User clarification: no receipt printing yet. Do not expose payment-record printing. Reports use the Android system Save as PDF option; no direct receipt-printer integration in this version.
